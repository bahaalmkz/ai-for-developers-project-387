# Встроенная H2 в файле и блокировка `calendar_lock` для записи

Данные хранятся во встроенной БД H2 в файле, без отдельного сервера: проекту не нужна инфраструктура, а данные переживают перезапуск. Единый календарь владельца требует, чтобы встречи любых типов не пересекались, поэтому проверка занятости и вставка встречи выполняются в одной транзакции под блокировкой строки таблицы `calendar_lock` (`SELECT ... FOR UPDATE`): параллельные записи выстраиваются в очередь, второй гость получает 409.

Рассмотрели уникальный индекс по времени (не выражает пересечение интервалов разной длины) и PostgreSQL (отдельный сервер ради учебного проекта).

Следствие: у H2 тайм-аут блокировки по умолчанию 2 секунды, при длительной очереди запись может завершиться ошибкой, а не 409. Смена СУБД потребует заново продумать блокировку.
